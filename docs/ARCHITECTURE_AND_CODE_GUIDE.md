## 1. نظرة عامة على المعمارية (Feature-First Architecture)

يتبع تطبيق «تَدْبِير» معمارية تعتمد على الميزات المستقلة (**Feature-First Modular Architecture**) المستوحاة من مبادئ العمارة النظيفة (Clean Architecture):

```
lib/
├── app/                # هيكل التطبيق: التهيئة، والتنقل، والترجمة، والتراخيص
├── core/               # الأساسات التي لا تعرف بيانات التطبيق (لا تستورد ما فوقها)
│   ├── design_system/  # الرموز، والبطاقات، والأزرار، والقوائم، والأيقونات
│   ├── motion/         # الحركة واحترام تقليلها
│   ├── theme/          # ثيمات الألوان الخمسة
│   └── utils/          # تطبيع العربية، والبحث بالجذر، واتجاه النص
├── data/               # بيانات التطبيق؛ تعتمد على core فقط
│   ├── models/         # نماذج البيانات ومستودعاتها
│   ├── quran/          # نص القرآن ونماذجه ومعاني الكلمات
│   └── storage/        # قاعدة SQLite ومخزن بيانات المستخدم
├── features/           # مجلد لكل ميزة؛ وفيه screens/ وwidgets/ وdata/ إذا تجاوزت ستة ملفات
│   ├── audio/          # التلاوة آيةً آية، والتشغيل في الخلفية، والتنزيل
│   ├── ayah_links/     # روابط الآيات، والعرض الشبكي
│   ├── backup/         # النسخ الاحتياطي المشفّر واستعادته
│   ├── bookmarks/      # شاشة الفواصل
│   ├── books/          # مكتبة الكتب والملازم، وقارئ PDF
│   ├── continue/       # المتابعة من حيث توقفت
│   ├── daily/          # آية اليوم
│   ├── duas/           # أدعية القرآن، وأذكار الصباح والمساء، وأدعية أهل البيت
│   ├── focus/          # وضع التأمل
│   ├── highlights/     # شاشة التظليل
│   ├── home/           # الشاشة الرئيسية
│   ├── journey/        # رحلة القراءة، والالتزام اليومي، والأهداف، وخريطة المصحف
│   ├── memorization/   # الحفظ بصناديق لايتنر
│   ├── more/           # تبويب المزيد
│   ├── notes/          # الخواطر، وتصديرها PDF والدفتر
│   ├── onboarding/     # الإقلاع الأول: الاسم والثيم
│   ├── pathways/       # مسارات التدبر
│   ├── qibla/          # اتجاه القبلة (GPS والبوصلة)
│   ├── quran/          # مصحف المدينة (QCF)، وعرض الصفحات، وإجراءات الآية
│   ├── reminders/      # التذكيرات ومجدول الإشعارات
│   ├── search/         # البحث الموحّد ومزوّداته
│   ├── settings/       # الإعدادات
│   ├── share/          # بطاقات مشاركة الآيات
│   ├── tadbeer/        # وقفة التدبر بأسئلتها الأربعة
│   ├── tasbeeh/        # الاستغفار والتسبيح
│   ├── widgets/        # ودجت الشاشة الرئيسية
│   └── word_meanings/  # مستكشف معاني الكلمات
├── l10n/               # ملفات الترجمة ARB
└── main.dart           # نقطة البداية: bootstrap() ثم runApp()
```

الاعتماد يسير في اتجاه واحد فقط: `features` ← `data` ← `core`. لا تستورد `core` ولا `data` أي ميزة؛ وحين تحتاج طبقة البيانات ميزةً (مجدول التذكيرات) يربطها `main` عبر واجهة (`ReminderScheduler`).

### 💡 لماذا تم اختيار هذا النمط؟
- **عزل الميزات (Feature Isolation):** كل مجلد ميزة يحتوي على نماذجها (`models`)، مستودع بياناتها (`repositories`)، وواجهاتها (`views`/`screens`).
- **سهولة الصيانة والتوسيع:** إضافة أي ميزة جديدة أو تعديل منطق ميزة قائمة يتم داخل مجلدها دون التسبب في آثار جانبية (Side Effects) لبقية أجزاء التطبيق.

## 2. إدارة الحالة وانسياب البيانات (State Management & Reactive Data Flow)

يعتمد التطبيق على أدوات فلاتر الأصلية خفيفة الوزن (`ValueNotifier`, `ChangeNotifier`, `ListenableBuilder`) بدلاً من المكتبات الخارجية الثقيلة:

```
[مستودع البيانات: Repository] ──(يحدث قاعدة البيانات SQLite)──> [UserDatabase]
             │
             ▼
    [UserDataStore] (واجهة تفاعلية مركزية Singleton)
             │
      (بث التحديث عبر Listenable / ValueNotifier)
             │
             ▼
   [واجهات المستخدم: Screens / Widgets] ──(إعادة بناء جزئية سلسة فقط للمكون المعني)
```

### مبادئ إدارة الحالة في التطبيق:
1. **الواجهة الموحدة (Facade Pattern):** كلاس `UserDataStore.instance` يعمل كـ Single Source of Truth للواجهات، حيث يحمل بيانات المستخدم النشطة في الذاكرة لتفادي القراءة المستمرة من القرص الصلب.
2. **التحديث الدقيق (Granular Rebuilds):** لا يتم عمل `setState` على مستوى الشاشات الكبيرة؛ بل تُستخدم عناصر مثل `ListenableBuilder` أو `ValueListenableBuilder` لإعادة رسم المكون الصغير المتأثر فقط، مما يوفر أداءً ثابتاً عند 60/120 إطاراً في الثانية.

## 3. هندسة التخزين وقواعد البيانات (Immutable Scripture vs Mutable User Data)

تعتمد هندسة البيانات في «تَدْبِير» على مبدأ جوهري حاسم:

> 🛡️ **مبدأ الفصل الصارم:** النصوص القرآنية والكتب والتفاسير مقدسة وثابتة (`Immutable`)، وتُفصل تماماً عن بيانات تفاعلات المستخدم القابلة للتغيير (`Mutable`).

```
┌──────────────────────────────────────────────┐
│  النصوص الثابتة (Assets / Read-Only JSON)    │
│  - المصحف الشريف العثماني (6236 آية، 604 ص)   │
│  - غريب القرآن ومعاني الكلمات                │
│  - كتب التراث والملازم وأدعية أهل البيت     │
└──────────────────────────────────────────────┘
                       ≠
┌──────────────────────────────────────────────┐
│  بيانات المستخدم المتغيرة (SQLite DB)        │
│  - الملاحظات الشخصية (Notes)                 │
│  - روابط الآيات وكروت الملاحظات (Ayah Links) │
│  - الفواصل والتظليلات والموضع الأخير         │
│  - إعدادات الخط والسمات وتفضيلات القراءة     │
└──────────────────────────────────────────────┘
```

### مزايا هذا التصميم:
1. **استحالة تلف النص القرآني:** لا يمكن لأي خطأ برمجي أو انهيار في قاعدة البيانات أن يُعدل أو يحذف حرفاً واحداً من آيات القرآن الكريم.
2. **نسخ احتياطي فائق الخفة:** ملف قاعدة بيانات المستخدم `tadbeer_user_data.db` لا يتجاوز حجمه بضع مئات من الكيلوبايت، مما يتيح تشفيره ومشاركته واستعادته في أجزاء من الثانية عبر `BackupCryptoService`.
3. **التشغيل الموحد عبر المنصات:** يتم استخدام محرك `sqflite_common_ffi` على بيئات سطح المكتب (Linux, Windows, macOS) وبيئة الاختبارات، بينما يعمل المحرك الأصيل على Android و iOS بسلاسة.

## 4. محرك البحث وتطبيع النصوص العربية (Arabic Search Normalization & Root Engine)

### 🧩 التحدي:
اللغة العربية غنية بالتشكيل وعلامات الوقف والتنغيم، وتختلف كتابة بعض الحروف بين الرسم الإملائي المعاصر والرسم العثماني المصحفي (مثل: `أ، إ، آ، ٱ`، أو التاء المربوطة `ة` والهاء `ه`، أو الألف الخنجرية في `إبراهيم` مقابل `إبرٰهِيم`).

### 🛠️ الحل البرمجي في `ArabicSearchNormalizer`:
1. **تجريد التشكيل والرموز:** تعبير نمطي (Regex) شامل يزيل علامات الحركات وعلامات السجدة والوقف والتطويل (الكشيدة).
2. **توحيد أشكال الهمزات والألفات:** دمج كافة أشكال الألف في ألف مجردة (`ا`).
3. **التطبيع المعجمي بين العثماني والمعاصر:** تحويل الكلمات القرآنية مثل `صلوة` إلى `صلاة`، و`زكوة` إلى `زكاة`، و`حيوه` إلى `حياة` لتطابق بحث المستخدم تلقائياً.
4. **تطبيع الأرقام (UX Fix):** عبر دالة `toEnglishDigits`، يتم تحويل الأرقام المشرقية (`٠-٩`) والأرقام الفارسية (`۰-۹`) إلى أرقام لاتينية قياسية (`0-9`) لضمان نجاح البحث والقفز بين صفحات المصحف من أي لوحة مفاتيح.
5. **البحث بالجذر الصرفي (`ArabicRootSearchHelper`):** استخراج الجذر الثلاثي تلقائياً واشتقاق كافة الصيغ الصرفية قرآنياً (مثال: بحث `جذر:صبر` يُطابق: `صابر`, `اصبر`, `اصطبر`, `صبورا`, `الصابرين`).
6. **تحويل النطق الصوتي للرسم القياسي في استعلامات البحث فقط (`normalizeSearchQuery`):**
   - يقوم المطبّع تلقائياً بمعالجة مدخلات البحث لتحويل الكلمات المكتوبة صوتياً أو إملائياً بالخطأ إلى الرسم الإملائي والعثماني القياسي المعتمد (مثل: `هازا -> هذا`, `هاذه -> هذه`, `هولاء -> هؤلاء`, `ذالك -> ذلك`, `لكن -> لكن`, `صلوه/صلاه -> صلاة`, `زكوه/زكاه -> زكاة`, `حيوه/حياه -> حياة`, `رحمن -> رحمن`, `الذين -> الذين`, `طه -> طه`).
   - 🛡️ **مبدأ الحصانة المطلقة:** هذا التحويل الصوتي ينحصر **فقط في معالجة استعلام البحث المكتوب في الواجهة**، ولا يمس إطلاقاً نصوص المصحف الشريف العثمانية، أو نصوص الأحاديث والأدعية، أو المعاجم والتفاسير.

## 5. واجهة المصحف الشريف وهندسة ساحة الإيماءات (Mushaf Typography & Gesture Arena)

### 📖 الطباعة الرقمية لصفحات المصحف:
- صُممت صفحة المصحف عبر `RichText` بمحاذاة تبريرية متناغمة تعكس المصحف المطبوع، حيث تُمثل كل آية بـ `TextSpan` متبوعة برمز نهاية الآية ورقمها عبر `WidgetSpan`.

### 🤼 ساحة الإيماءات في فلاتر (Flutter Gesture Arena) وكلاس `AyahGestureRecognizer`:
- **المعضلة:** يحتوي المصحف على `PageView` للتمرير الأفقي بين 604 صفحات. في المقابل، يحتاج المستخدم للنقر السريع لتظليل الآية، أو الضغط المطول لإظهار قائمة الخيارات (`AyahActionSheet`). استخدام `GestureDetector` عادي داخل `RichText` مستحيل برمجياً، واستخدام متعرفين عاديين يتسبب في تنازع يلغي حركة التمرير أو يؤخر الاستجابة.
- **الحل:** وراثة `LongPressGestureRecognizer` المخصص:
  1. **عند اللمس (`PointerDown`):** تلوين خلفية الآية فوراً كاستجابة بصرية مبكرة.
  2. **عند رفع الإصبع مبكراً (`PointerUp`):** إذا لم ينقضِ وقت المهلة (1100ms)، يُلغى التظليل ويُقبل الحدث كـ `onTap`.
  3. **عند انقضاء المهلة (`didExceedDeadline`):** ينطلق `onLongPress` لإظهار خيارات الآية مع اهتزاز لمسي خفيف (Haptic Feedback).
  4. **عند التمرير الأفقي:** تكسب ساحة الإيماءات التمرير الخاص بـ `PageView` وتلغي الآية عبر `PointerCancel` فيختفي التظليل دون تعطيل التمرير.

## 6. شبكة روابط الآيات والرياضيات التحويلية (Ayah Links Canvas & Radial Trigonometry)

توفر شبكة روابط الآيات كانفاساً تفاعلياً متقدماً يستند إلى `InteractiveViewer` بمساحة افتراضية شاسعة (3000 × 3000 بكسل):

### 📐 الرياضيات الهندسية للتوزيع التلقائي (`_computeAutoLayoutPositions`):
تُوزع كروت الآيات والملاحظات حول العقدة المركزية `(1500, 1500)` باستخدام الإحداثيات القطبية:

$$\theta = \frac{2 \pi \cdot i}{N} - \frac{\pi}{2}$$
$$x = x_{\text{center}} + r \cdot \cos(\theta)$$
$$y = y_{\text{center}} + r \cdot \sin(\theta)$$

```
               [كارت آية 1]
                    ▲
                    │  r (نصف القطر متكيف مع حجم الخط)
                    │
   [كارت ملاحظة] ◄──●──► [كارت آية 2]
                (1500, 1500)
                    │
                    ▼
               [كارت آية 3]
```

- **الحلقات متحدة المركز (Concentric Rings):** عند زيادة عدد العقد عن 18، تُنشئ الخوارزمية حلقات دائرية متتالية، مع تدوير كل حلقة بمقدار $\frac{\pi}{5}$ لمنع تراصف العقد فوق بعضها شعاعياً.
- **منحنيات بيزييه التربيعية (Quadratic Bézier):** ترسم خطوط الربط بين المركز والعقد بنعومة فائقة عبر `quadraticBezierTo` باستخدام نقطة تحكم وسطية $C = \frac{P_1 + P_2}{2}$.

## 7. الرسم المتجهي البرمجي وزخارف المصحف (Vector Painting with CustomPainter)

بدلاً من تضمين صور ذات أحجام كبيرة قد تفقد حدتها أو تستهلك الذاكرة، تُنفذ إطارات المصحف والقناديل الزخرفية بالكامل برمجياً عبر `CustomPainter`:

- **كلاس `MushafPageFramePainter`:** يرسم الإطار المذهب الدقيق وممر الهامش وزوايا الأرابيسك الإسلامية كمسارات هندسية نقية (`Path`).
- **كفاءة إعادة الرسم:** دالة `shouldRepaint` ترجع `false` دائماً ما لم يتغير وضع الإضاءة (Dark / Light Mode)، مما يسمح لمحرك الرسم في فلاتر (Impeller/Skia) بالاحتفاظ بطبقة العرض في الذاكرة دون استهلاك لوحدة المعالجة الرسومية (GPU).

## 8. نظام الألوان وإمكانية الوصول (Color Harmony & Accessibility)

صُمم نظام الألوان في كلاس [`AppColors`](../lib/core/theme/theme.dart) مستلهماً من فنون تذهيب المصاحف القديمة وورق المخطوطات الدافئ:

- **ألوان الوضع النهاري:**
  - خلفية الورق (`#F6F3EA` و `#F1EBDD`): تقليل إجهاد العين مقارنة بالأبيض الساطع.
  - اللون الأساسي (`#29483A` - الزيتوني العميق): يمنح وقاراً وسكينة بصرية.
  - الذهب المعتّق (`#A88A55`): يُبرز العناوين والإطارات وحليات الآيات.
- **ألوان الوضع الليلي:**
  - أسود مخفف هادئ مع درجات رمادية دافئة لمنع التباين الحاد المجهد للعين في الظلام.
- **معايير الوصولية (WCAG AA):** تحقق جميع نصوص التلاوة والواجهات نسب تباين تتجاوز `4.5:1` لسهولة القراءة لجميع فئات المستخدمين.

## 10. منظومة التصميم الرقمي المستقبلي والحركة (Futuristic Design System & AppMotion)

### 💎 فلسفة التصميم (Tadbeer Futuristic Digital Experience):
صُممت واجهات تطبيق تدبير لتجمع بين الرصانة والسكينة الروحانية للقرآن الكريم، والطابع الهندسي الرقمي المستقبلي عبر حزمة تصميم مركزية تحت مجلد `lib/core/design_system/`:

1. **الرموز والتنسيقات (`AppTokens`):**
   - نصف أقطار الحواف: `radiusSm: 8.0`, `radiusMd: 14.0`, `radiusLg: 20.0`, `radiusXl: 28.0`.
   - الحدود الدقيقة متعددة الطبقات: `borderWidthSubtle: 0.8`, `borderWidthFocused: 1.5`.
   - حزم الظلال الخفيفة غير المشتتة (`ambientShadow`, `elevatedShadow`).
2. **البطاقة المستقبلية (`FuturisticCard`):**
   - توفر خلفية متدرجة ذات شفافية متدرجة دقيقة، وحواف مقطوعة هندسياً، ودعماً للحدود النشطة عند التركيز (`isFocused`) أو الضغط.
3. **الأزرار والشارات التفاعلية (`FuturisticButton`, `FuturisticBadge`, `FuturisticIconButton`):**
   - تدعم التباين العالي، والتحويم السلس (Hover)، والمؤشرات اللمسية اللحظية.

### 🎬 محرك الحركة الموحد وإمكانية الوصول (`AppMotion`):
يقع المحرك في `lib/core/motion/app_motion.dart`:
- **مدد زمنية موحدة:**
  - `fast`: `120ms` (للانتقالات الدقيقة والضغطات).
  - `normal`: `200ms` (لتوسيع البطاقات وتبديل الحالات).
  - `slow`: `350ms` (لانتقال الصفحات واللوحات السفلية).
- **المنحنيات التكعيبية:** `Curves.easeOutCubic` و `Curves.easeInOutCubic` لضمان فيزيائية انسيابية طبيعية.
- **مكوّن `ScaleOnPress`:** مكوّن تغليف خفيف يوفر ارتداداً متناسقاً عند النقر بنسبة تصغير `0.97`، مع اهتزاز لمسي مدروس.
- **معيار تقليل الحركة (Reduced Motion):**
  عبر `AppMotion.isReduceMotion(context)` المستندة إلى `MediaQuery.disableAnimationsOf(context)`، تُعطّل الحركات تلقائياً عند تفعيل المستخدم لإعداد تقليل الحركة في جهازه، وتتحول الواجهة فورياً إلى الحالات النهائية لحماية المستخدمين الحساسين للحركة.
